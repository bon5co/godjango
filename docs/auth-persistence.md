# Auth persistence

The default auth store uses Bun and PostgreSQL behind the existing auth domain
interfaces:

```go
store := auth.NewBunStore(db)
manager := auth.NewManager(store, auth.NewPasswordHasher())
```

Applications may replace `UserStore`; callers do not receive Bun models,
queries, or transactions.

Register `auth.App` in the project to include the default transactional
migration. It creates:

- users
- groups
- permissions
- user/group memberships
- direct user permissions
- group permissions
- database sessions and expiry index

PostgreSQL enforces unique usernames, group names, permission identities, and
join-table pairs. User and relation identifiers are UUIDs generated by
PostgreSQL.

## Access changes

Permission identities retain Django's stable `app.codename` form:

```go
err := store.CreatePermission(ctx, "books.change_book")
err = store.CreateGroup(ctx, "editors")
err = store.AddUserToGroup(ctx, user.ID, "editors")
err = store.GrantGroupPermission(ctx, "editors", "books.change_book")
```

Creation and grants are idempotent. Concurrent identical grants produce one
database row. Bundle related changes under the store-owned transaction boundary:

```go
err := store.RunInTx(ctx, func(ctx context.Context, tx *auth.BunStore) error {
	if err := tx.CreatePermission(ctx, permission); err != nil {
		return err
	}
	return tx.GrantUserPermission(ctx, user.ID, permission)
})
```

`UserByUsername` loads direct permissions, groups, and group permissions back
into the domain `User`. Permission evaluation stays in `ModelBackend`.

Future `createsuperuser` and `changepassword` commands must call `Manager` and
this store. They must not issue bespoke SQL.

## Sessions

`SaveSession` performs an upsert. Session data is copied at the API boundary so
callers cannot mutate stored or returned byte slices accidentally.

`DeleteExpiredSessions` supports scheduled cleanup. PostgreSQL stores timestamps
at microsecond precision. The HTTP/session adapter will reject expired sessions
at request time; cleanup is storage maintenance, not the security boundary.

## Verification

Tagged tests require a dedicated database:

```bash
GODJANGO_TEST_DATABASE_URL=postgres://... \
	go test -tags=integration ./auth
```

The suite verifies migrations and every write at row level, concurrent username
and permission races, transaction rollback, access reconstruction, and session
round trips, updates, deletion, and expiry cleanup.
